01 — Three products, one question

What do you hold
at the end?

Same Claude underneath. The difference is what it can reach — and what it hands back.

Claude

You get words. Nothing lands on your machine.

Good for

  • Talking a problem through
  • A first draft of anything written
  • Reading an image or a PDF
Reaches what you paste

Cowork

You get a finished document — built out of your own material.

Reach for it when

  • Nobody wants to open a terminal
  • The sources sit in Drive, mail or Slack
  • The output is Word, Excel or PowerPoint
  • Teammates watch the same thread
Reaches the apps you connect

Claude Code

You get a thing that switches on — and a link to it.

Only it can

  • Run what it wrote and fix its own errors
  • Open a live preview in your browser
  • Use Git — every version, roll back anytime
  • Publish it to a public URL
  • Act on 500 files sitting on your drive
Reaches the whole folder on your disk

04 — Where it lives

Workbench, or server room.

One you open yourself this afternoon. The other goes through IT.

GitHub

Like a printed board in the lobby.

It goes up finished, and it reads the same to everyone who walks past. Nobody is there to answer a question — that is static. Good for project pages, viewers, 360 tours, calculators, a deck like this one.

Who sees it
Everyone. A free Pages site is a public repo — history included.
Address
yourname.github.io/project
Limits
No logins, no shared saving, no live firm data. A file over 50 MB gets a warning; over 100 MB GitHub refuses the upload.

Front end only — nothing behind the board

Azure

Like a staffed desk in the same lobby.

Someone is there. They check your badge, pull the right file, and note down what you tell them — so every visitor leaves with a different answer. That is dynamic. Good for firm data, logins, anything with a database.

Who sees it
Only the office. Behind firm accounts, and IT can audit it.
Address
project.azurestaticapps.net
Needs
An IT request, a budget, an approval.

Front end + back end — the desk, and the room behind it

This deck is a static site. On sheet 06 your board saves to your own browser — which is why the person next to you cannot see it. That gap is exactly what a back end is for.

Two rules,
no exceptions

Public is forever. Deleting a file doesn't unpublish it — rotate the key instead.
No keys, no client data, no project files. Write a .gitignore before the first commit.

07 — Wrap

Don't study it.
Build one.

Rule 01

One change at a time

Look at it, then save a version. Batch five and you'll never find the one that broke it.

Rule 02

Keys and firm data stay off

Treat every push like a public post. Would you be fine with anyone seeing it?

Rule 03

Stuck means thin brief

Say who it's for, what it does and how it should look — once more. That usually unblocks it.
